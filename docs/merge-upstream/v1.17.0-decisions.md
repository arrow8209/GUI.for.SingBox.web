## 关键决策：core-api 重构 vs 本地 Core Proxy

上游 `8ab245e refactor(core-api): centralize REST and WebSocket logic into api layer` 把内核访问从 inline 代码改成统一的 `Request` + `WebSockets` 类（`@/api/request.ts` + `@/api/websocket.ts`）。**架构方向**：上游让前端直连内核 HTTP/WS。

本地的 Core Proxy 架构（`/api/core/*` + `X-Core-Base`/`X-Core-Bearer` headers，main.go 的 `handleCoreProxy` 既支持 HTTP 也支持 WebSocket upgrade）必须**完整保留**——它是 Web fork 的关键鉴权与隔离基础设施。

**决策**：
- 采纳上游引入的 `Request` 类（已在合并中自动融合本地 `useAuthStore` token 注入）
- 采纳上游引入的 `WebSockets` 类
- **拒绝上游"前端直连内核"的 setupCoreApi('http'|'ws')** —— 在 `frontend/src/api/kernel.ts` 中重写为：
  - HTTP `setupKernelApi`：保留 `request.headers = { 'X-Core-Base': ..., 'X-Core-Bearer': ... }` 走本地 Core Proxy
  - WebSocket：实现搬到 `stores/kernelApi.ts` 的 `initCoreWebsockets`，用 `WebSockets` 类 + `coreBase`/`coreBearer`/`token` 通过 query 传给 Core Proxy（main.go 的 `handleCoreProxy` 已支持）
